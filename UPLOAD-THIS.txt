WHAT TO DO WITH THIS ZIP (GitHub Pages) — UPDATE v5
====================================================
What changed since the last update — the fault timeline in the ADMIN PANEL
(it does not appear in the app at all):
  - The timeline is now FULLY EDITABLE by the admin: every point (open or
    archived) has an edit button (✏️) to change its note, location, start
    date, and fix date. Edits sync to every device automatically.
  - Everything else from the last update stays: two lists (open faults /
    archive of fixed ones), fixed faults show when they started, when they
    were fixed, and HOW LONG they took; each list shows 5 entries with a
    "see more" button; newest at the top; archived points can be deleted
    (🗑) and the whole timeline exported to CSV (💾).

REPLACE these two files in your repo (they already exist there):
  - index.html
  - sw.js                   (CHANGED too — new offline-cache name, so every
                            phone downloads the new sync.js automatically)

ADD these six files (new or updated):
  - sync.js                   (updated - the sync engine)
  - admin.html                (updated - editable two-section timeline archive)
  - firebase-config.js        (your real config - already filled in)
  - firebase-config.example.js
  - SETUP.md                  (updated - read this, it is your checklist)
  - UPLOAD-THIS.txt           (this file)

DO NOT touch: manifest.json and the icon-*.png files (unchanged).

GitHub Pages steps:
  1. Go to your repo on github.com -> "Add file" -> "Upload files".
  2. Drag ALL files from this zip into the upload box (root of the repo).
     Existing index.html and sw.js will be overwritten - that is intended.
  3. Commit.
  4. Repo -> Settings -> Pages -> Source: "Deploy from a branch" ->
     Branch: main -> Folder: / (root) -> Save.
  5. Wait ~1 minute, open the site URL.
  6. Phones pick up the new sync.js by themselves the next time they open the
     app (the offline-cache name changed). If one still misbehaves: open the
     app and press Ctrl+Shift+R once.

BEFORE or right after uploading (Firebase console, project "mag-toran"):
  1. Enable Firestore (if not yet): console.firebase.google.com/project/mag-toran/firestore
     -> Create database -> location me-west1 (Tel Aviv) -> production mode.
  2. UPDATE the security rules: paste the rules from SETUP.md (step 3) into
     Firestore -> Rules again — they now also cover the "faultTimeline"
     collection (without this the timeline will not sync).
  3. Get the VAPID key: console -> Cloud Messaging -> Web Push certificates
     -> Generate key pair -> paste into firebase-config.js (replace
     REPLACE-ME-WITH-YOUR-VAPID-KEY). Only needed for push notifications.

CLEANING UP / FIXING YOUR TEST DATA:
  - The app no longer shows the timeline at all — the screen is clean.
  - Open admin.html -> the timeline has two lists: open faults and archive.
  - To fix a mistake in a point (wrong note/date): press its ✏️ button and
    edit it — the fix syncs to every device.
  - To remove a test point: press its 🗑 button (archived/fixed points only).
  - 💾 exports the whole timeline to CSV if you want a copy first.

Then test: open the app on two phones. Mark a car as defective on one — it
appears on the other within a few seconds and STAYS until someone marks it
fixed. Open admin.html for the admin view + the editable timeline archive.
